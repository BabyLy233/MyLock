# 下载镜像源

## 结论

能做。原项目里的「镜像源」指的是 **GameBanana 自己的文件服务器**
（`filecacheNN.gamebanana.com`），不是项目自建的 mirror-service。设置页
「网络 → 下载路由」里可以选「默认 / 自动 / 指定某台服务器」，选择结果在真正
发起下载时才被拼进地址。

本项目直接用 GameBanana 的 API，没有自建后端，所以这套东西可以原样搬过来，
而且需要的字段（文件名、大小、MD5）现在都拿得到。

## 现状（已完成，2026-10-22）

- `internal/gb/fileservers.go`：读 `Util/Fileservers`、过滤非法域名、6 小时缓存、
  `Fileserver.URL` 拼地址、`PickFileserver` 按偏好挑。
- `internal/download`：新增 `Probe`，测速复用下载的域名白名单。
- `internal/config`：新增 `fileserverPreference` 与 `fileserverLatencyMs`。
- `internal/app/fileservers.go`：状态、懒加载、测速、下载地址解析，以及设置页的
  「下载路由」一节；安装和更新两条路径都经过它。
- 服务器列表是三列卡片网格：状态圆点、名称、状态 / 速率 / 延迟各占一行，选中
  的卡片用强调色描边加浅色填充，键盘焦点画在卡片上。
- 设置页改成可滚动：服务器列表最多二十多行，短窗口里下面的节否则到不了。
- 实测三种类型的直链都能取：`mods`、`sounds`、`wips` 均返回 206（Range）。

## 原项目怎么做的

### 1. 服务器列表

```
GET https://gamebanana.com/apiv11/Util/Fileservers?_nPage=1
```

2026-10-22 实测返回 21 条，字段如下：

| 字段 | 含义 |
| --- | --- |
| `_idRow` | 服务器 id，偏好里存的就是它 |
| `_sDomain` | 子域名，如 `filecache20` |
| `_sState` | `up` / `down` / `terminated` |
| `_aStats._a1hr._fRate` | 最近一小时平均字节/秒，`auto` 按它挑 |
| `_aStats._a1hr._nRequests` | 最近一小时请求数，只用于显示 |

读取在 Rust 的 `apps/desktop/src-tauri/src/commands/gamebanana_catalog/state.rs`：

- 丢掉 `_sDomain` 为空、或含字母、数字、`-` 以外字符的记录；
- 完整域名拼成 `{_sDomain}.gamebanana.com`；
- 生成模板 `https://{domain}/{category}/{filename}`；
- 进程内缓存 6 小时。

### 2. 三种偏好

`fileserverPreference` 存在前端的持久化 store 里
（`apps/desktop/src/lib/store/slices/network.ts`），三种取值：

- `"default"`（默认）：不换地址，用 API 给的 `_sDownloadUrl`，即
  `https://gamebanana.com/dl/<文件 id>`，它自己 302 到
  `files.gamebanana.com`；
- `"auto"`：在 `_sState == "up"` 的服务器里取 `_a1hr._fRate` 最大的一台；
- 具体的服务器 id 字符串：用它，只排除 `terminated`。

真正换地址的不是前端，是下载命令：`queue_download` →
`resolve_gamebanana_file`（`apps/desktop/src-tauri/src/commands/downloads.rs`）。

拼接规则：

```text
https://<domain>/<mods|sounds|wips>/<URL 编码后的文件名>
```

- 路径段按提交类型：Mod → `mods`，Sound → `sounds`，Wip → `wips`
  （`providers/submission_ref.rs` 的 `gamebanana_path`）。
- 文件名必须用 `_sFile`（磁盘上的真实文件名），不是 `_sName`（显示名）。
  本项目的 `gb.File.Name` 读的正好是 `_sFile`，可以直接用。
- 实测直链可用：
  `https://filecache20.gamebanana.com/mods/yamato_red_d0d08.rar` 返回 200；
  带 `Range: bytes=0-99` 返回 206，所以现有的断点续传逻辑不受影响。

回退规则：

- 偏好是 `default`：不请求服务器列表，直接用原地址；
- 服务器列表读取失败：记一条 warn，用原地址；
- `auto` 没有 `up` 的服务器：用原地址；
- 指定的 id 在列表里找不到：用原地址；
- 指定的服务器存在但状态是 `down`：**仍然用它**，原项目只排除 `terminated`。

### 3. 设置页

`settings → 网络 → 下载路由`（`components/settings/fileserver-settings.tsx`）：

- 模式：两张卡片「默认」「自动」；
- 服务器列表：状态圆点、名称、最近一小时速率、延迟；点一张卡就是选它；
- 「刷新列表」「测试服务器」两个按钮；
- 测速：并发 `HEAD https://<domain>/tools/deadlockmodmanager-v050.zip`，
  5 秒超时、不跟随重定向；只要收到响应就算可达（不检查状态码），耗时记为延迟；
- 延迟结果按服务器 id 存进 store，和偏好一起持久化。

有个容易看错的地方：前端 `lib/download/fileserver.ts` 里还有一份
`resolveDownloadFileUrls`，会「延迟优先、否则吞吐」挑服务器，但全仓库没有
调用点，是死代码。实际安装走上面的 Rust 路径，`auto` **只看吞吐，不看延迟**；
延迟只用于界面显示。

另外原项目的「刷新列表」按钮实际调用 `get_gamebanana_fileservers` 时把
`forceRefresh` 写死成 `false`，所以 6 小时内刷新仍然读缓存。这更像是疏忽，
本项目可以按按钮的字面意思让它真正强制刷新。

### 4. 另一个「镜像」，不是这个功能

原 monorepo 里还有 `apps/mirror-service`：把模组文件缓存到 S3，API 在功能开关
`mod-download-mirroring` 打开时把下载地址换成
`https://mirror.deadlockmods.app/download/<modId>/<fileId>`。它由服务端决定，
客户端选不了，也不在这个 TODO 的范围里。本项目没有自建后端；不过
`internal/download/download.go` 的域名白名单里已经有 `deadlockmods.app`，
将来要接也不难。

## 本项目现状（开发前）

- `internal/gb` 只读 `_sDownloadUrl`（`models.go` 的 `fileJSON.URL`），没有
  Fileservers 接口。
- `internal/download` 只放行 https 和 `gamebanana.com` / `deadlockmods.app`
  及其子域（`download.go` 的 `allowed`）。`filecacheNN.gamebanana.com` 本来就在
  白名单里，不需要改。
- `internal/config` 里没有任何网络相关的设置。
- 下载入口有两个，都必须换地址，否则「更新」会绕开用户选的镜像：
  - 安装：`internal/app/storeinstall.go` 里的 `a.downloads.Get(...)`
  - 更新：`internal/app/updates.go` 里的 `a.downloads.Get(...)`
- 两处都能拿到 `gb.Kind`：安装来自 `gb.Submission.Kind`，更新来自
  `submissionRef(id)` 解析出的类型。

## 实现（已完成）

### 1. `internal/gb`：读服务器列表

新增 `internal/gb/fileservers.go`：

```go
type Fileserver struct {
    ID    string // _idRow
    Name  string // _sDomain
    Domain string // {_sDomain}.gamebanana.com
    State string // up / down / terminated
    Rate  int64  // _a1hr._fRate，字节/秒
}
```

- `Client.Fileservers(ctx)` 请求 `Util/Fileservers?_nPage=1`，复用现有的
  `get`、限速和重试。
- 解析时按原项目规则过滤域名，非法记录直接丢掉，不要构造出可下载的地址。
- 在 `Client` 上做 6 小时缓存（加锁），并提供强制刷新的入口。缓存放在 `gb`
  而不是 `app`，因为 TTL 属于这个接口。
- 补一个 `Fileserver.URL(kind Kind, filename string) string`，把 Kind 映射成
  `mods` / `sounds` / `wips`，文件名用 `url.PathEscape` 编码。

### 2. `internal/config`：记住选择

`Config` 增加两个字段（沿用 camelCase，缺省即可，旧文件读进来自然是零值）：

```go
FileserverPreference string           `json:"fileserverPreference,omitempty"`
FileserverLatencyMs  map[string]int64 `json:"fileserverLatencyMs,omitempty"`
```

空字符串按 `"default"` 处理。`saveSettingsFor` 里补上这两个值。

### 3. `internal/app`：状态与解析

- `state`（快照）增加：服务器列表、偏好、延迟、加载中 / 错误。
- `start` 时读偏好；服务器列表可以等到设置页打开或第一次下载时再拉，避免启动
  多一个请求。
- 新增一个解析函数，由两条下载路径共用：

```go
func (a *app) downloadURL(ctx context.Context, kind gb.Kind, file gb.File) string
```

  逻辑照原项目：偏好为 default 直接用 `file.URL`；否则从列表里按偏好挑一台，
  挑不到就回退 `file.URL`。列表为空且偏好不是 default 时，在下载协程里先拉
  一次（走 6 小时缓存），失败再回退，不要因为镜像不可用而让安装失败。
- 选中的服务器如果已从列表里消失，回退 default；状态是 `down` 的仍按指定 id
  使用，与原项目一致。

### 4. 设置页：加「下载路由」

在「设置」页加一节（放在「外观」和「图片缓存」之间），标题用「下载路由」：

- 用一个 `ui.RadioGroup` 列出三种选择：默认、自动、以及列表里的每一台服务器。
  （没有用 `ui.Segmented`：它只有「默认 / 自动」两段，指定了某一台时无法表示
  「两段都没选」。）
- 服务器列表：名称、状态、速率、延迟。点一下就保存偏好。
- 「刷新列表」真正 force 拉取；「测试服务器」在后台协程里测，结果经
  `publish` 回到主线程再 `invalidate`，遵守 ARCHITECTURE 的线程模型。
- 列表为空或加载失败时显示原因，不影响下载（仍走默认地址）。
- 设置页整体套一层 `ui.Scroll`：服务器可能有二十多台，短窗口里不能有够不到的节。

### 5. 延迟测试

- 给 `internal/download` 加一个 `Probe(ctx, address) (time.Duration, bool)`：
  复用同一个域名白名单，`HEAD`，5 秒超时，不跟随重定向；收到任何响应都算可达。
- 测试路径用原项目的 `tools/deadlockmodmanager-v050.zip`（实测该文件在各文件
  服务器上存在，HEAD 返回 200）。

### 6. 测试

- `gb`：解析实测样例（21 条）、过滤非法域名、`URL` 拼接（空格 / 中文 / `#`
  等需要转义的字符）、Kind → 路径段。
- `gb`：`auto` 选速率最高的 `up` 服务器；没有 `up` 时返回空。
- `app`：偏好 default 不改地址；指定 id 生效；id 不在列表时回退；列表拉取失败
  时回退。
- `download`：`Probe` 的超时、不可达与非 https 地址。

## 验证方式

- 单元测试之外，手动装一个模组，分别用三种模式抓请求，确认实际命中的主机：
  default 应看到 `gamebanana.com/dl/...` → `files.gamebanana.com`；
  指定 / auto 应直接命中 `filecacheNN.gamebanana.com`。
- 下载中途断开网络再恢复，确认从镜像地址续传仍然有效（已实测服务器支持 Range）。
- 断网或让镜像列表接口失败一次，确认安装仍能走默认地址完成。

## 不做的

- 不做按延迟自动挑服务器。原项目实际路径只看吞吐，延迟只显示；照抄即可，避免
  与上游行为分叉。
- 不接 `mirror-service`。那是原项目服务端的开关，客户端没有选择入口。
