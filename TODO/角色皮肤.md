# 角色皮肤

## 现状（已完成，2026-10-22）

第 1 到 4 节已经实现：

- `library.json` 的条目新增 `heroOverride`（空 = 自动，`generic` = 通用/其他），
  其余字段沿用安装时写入的商店信息。
- `internal/heroes` 负责名字归一化、别名 / 短语猜测和 Skins 子分类解析；
  分类树仍是角色列表的来源，读不到 API 时用内置名单兜底。
- 侧栏新增「角色皮肤」页（`/skins`）：左侧角色列表（有模组的在前、搜索、
  头像、数量、当前皮肤 / 默认 / 冲突），右侧皮肤网格（穿上 / 脱下、删除、
  原帖、「浏览更多皮肤」跳到商店并按该角色筛选）。
- 「模组管理」每行显示角色，并有「角色…」对话框手动指定 / 恢复自动 /
  通用/其他。
- 一个角色默认只穿一套皮肤：穿上会先停用同角色其它皮肤；商店安装时若冲突，
  问「取消 / 两者都留 / 交换」。设置页两个开关：允许同穿多套（默认关）、
  安装时提醒冲突（默认开）。已同时启用的多套只在角色页标冲突，不自动改动。

第 5 节（额外内容、随机换皮肤、头像 / 3D 预览、VPK 内部模型检测）仍未做。

## 开发前的现状

- **商店**已经能按分类 / 子分类筛选：Skins 下正好是 44 个英雄，选一个就只
  看这个英雄的皮肤（`TODO/筛选.md`）。但这只影响浏览，不影响已安装的模组。
- **模组管理**页只知道 `.dmm.json` 里的模组 id 和文件名，不知道模组的名字、
  分类和角色，所以现在没法按角色分组，列表里也只能显示 id。
- 启用开关是逐个模组拨的，**没有「一个角色同时只能穿一套皮肤」的约束**。
- 已经有多个配置档（见 `TODO/多Profile.md`）：每个 profile 有自己的模组清单
  和文件，角色归属和皮肤互斥应该按当前 profile 的已安装模组来算。

原项目把已安装模组的信息放在自己的持久化模组库里（不在 `.dmm.json` 里），
每条记录有 `name` / `category` / `hero` / `detectedHero` / `heroOverride` /
安装顺序等，角色页和冲突提示都读这份数据。

## 原项目怎么做（行为参考）

### 角色归属

优先级从高到低：

1. 用户手动覆盖（`heroOverride`，可以改成任意角色，也可以改成「通用/其他」，
   或恢复自动）。
2. API 给的 `hero` 字段。
3. 模组名字猜测：内置 44 个英雄的别名表（`DeadlockHeroes` +
   `HERO_DEFINITIONS`）。
4. VPK 里的内部模型路径检测（`@deadlock-mods/hero-parser`，从条目路径里取
   内部名再查表）。
5. 都没有 → 不属于任何角色。

### 「角色皮肤」页

- 左侧英雄列表：有模组的角色排在前面；未发布但已经有模组的角色也显示；
  带搜索框；每行显示头像、名字、模组数，以及当前皮肤名 /「默认」/冲突警示。
- 右侧是选中角色的皮肤网格：皮肤卡片显示当前是否穿着，可切换、预览、删除、
  「分配给这个角色」（给没识别出角色的模组手动指定）。
- 「浏览更多皮肤」跳到商店，并自动带上这个角色的筛选。
- 皮肤和「额外内容」分开：Skins / Model Replacement 算皮肤；武器音效、
  技能音效、语音、击杀音效、音乐等算额外内容，额外内容默认不列出来，要在
  设置里打开「按角色显示额外内容」。
- 3D 预览是 Foundry 模型渲染，另一大块，先不做。

### 一个角色同时只能一套皮肤

- 角色页里皮肤是 **exclusive**：选一套新的，先把旧的停用再启用新的；再点
  当前这套就是脱掉（回到默认皮肤）。文件不删，只停用。
- 商店安装时如果该角色已经有启用的皮肤，弹确认框：**交换**（停用旧的、装
  新的）/ **两者都留** / **取消**。设置里可以关掉这个提醒，默认开。
- 设置「允许同一角色同时启用多套皮肤」默认关。打开后角色页的点击变成逐套
  开关，多个同时启用只在角色列表上标冲突，不再阻止。
- 模组管理页的通用开关不强制互斥；冲突由角色页显示出来。

## 要做（按依赖顺序）

### 1. 已安装模组的元数据（前置）

- 在配置目录放一份 `library.json`（**不要写进 `.dmm.json`**，格式要和原项目
  保持兼容），按模组 id（`Slug()`）记录：名字、类型（Mod / Sound / Wip）、
  根分类、子分类（皮肤的英雄通常在这里）、作者、安装时间、手动角色覆盖。
  先继续用 JSON，理由见 `TODO/多Profile.md` 的「存储：先不用 SQLite」；以后
  做本地 catalog 时可以把它并进 SQLite。
- 从商店安装时写入这些字段；来源就是 `gb.Submission`。
- 没有元数据的模组（旧版本装的、Tauri 版装的、手动放进去的）照常显示 id，
  角色未知；允许手动指定。
- 文件损坏/缺失时退回空表，不影响安装和清单。

### 2. 角色归属

- `internal/` 新增角色解析：手动覆盖 > 元数据里的子分类（仅皮肤类分类）>
  名字别名表 > 未知。
- 别名表可以照原项目移植（英雄名单 + `HERO_DEFINITIONS` 的别名/模糊词）。
  浏览器里的角色列表仍以 API 的分类树为准，不靠硬编码名单。
- 「模组管理」每行显示名字（有元数据时）和角色；没有角色的归到
  「通用/其他」。
- 手动指定角色的入口：模组管理页的行或详情里一个下拉，选项来自 Skins 分类树；
  有「恢复自动」和「通用/其他」。

### 3. 按角色查看

- 新增页面 `/skins`（侧栏「角色皮肤」）。
- 左侧列表：API Skins 分类树里的 44 个角色 + 手动指定的未知角色；有模组的
  排前面；搜索；显示模组数和当前皮肤名 /「默认」/ 冲突标记。
- 右侧：选中角色的皮肤网格。每张卡片显示名字、启用状态，操作：穿上/脱下、
  删除、查看商店里该角色的更多皮肤。
- 「浏览更多皮肤」复用现有筛选：跳到商店，把分类设为 Skins、子分类设为该
  角色。需要给 `store` 一个从外部设置筛选并搜索的入口。
- 额外内容分组放后面，先只做皮肤（Skins / Model Replacement）。

### 4. 一个角色一套皮肤

- 角色页穿上皮肤：把该角色其它已启用的皮肤 `SetEnabled(false)`（文件保留），
  再启用目标；一次只处理一个角色，和文件操作共用 `reading` 锁；游戏运行中
  拒绝。
- 再点当前皮肤 = 停用它，回到默认外观。
- 商店安装：安装/启用之前解析新模组的角色；如果该角色已有启用的皮肤，弹
  `ui.AlertDialog`：「交换」/「两者都留」/「取消」。「交换」先停用旧的再装；
  「取消」中止整个安装；「两者都留」照常装。只考虑皮肤类模组，额外内容不
  参与。
- 设置页增加两个开关：「允许同一角色同时启用多套皮肤」（默认关）、
  「安装时提醒角色冲突」（默认开）。
- 已启用的多套皮肤在角色列表上标冲突（当「允许多套」关着时）。
- 老数据里已经同时启用多套皮肤的，不自动改，只在界面上标出来，让用户自己
  处理。

### 5. 之后再做

- 额外内容（武器/技能/语音/音乐）按角色分组，设置开关默认关。
- 皮肤随机器：启动前给有池子的角色随机换一套，默认皮肤也可作为结果，连续
  两次不重复。依赖稳定的卸载/安装管线。
- 英雄头像、3D 预览（Foundry）。
- 从 VPK 内部模型路径识别角色（现在先用分类和名字）。
- 按 profile 分别记录？原项目的角色覆盖是全局模组库属性，建议保持一致；
  要改的话在 `TODO/多Profile.md` 里统一决定。

## 注意

- 现有数据里「启用」就等于「装了并且在加载」，没有原项目那种「已下载未安装」
  状态；互斥逻辑只需要看启用的模组。
- 角色页和商店的角色筛选应该是同一套分类名；别维护两份英雄名单，除非是为
  了给没有 API 数据的名字猜角色。
- 所有停用/启用都要走 `Profile.SetEnabled`，不要直接改文件或清单。
