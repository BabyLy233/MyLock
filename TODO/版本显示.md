# 版本显示

## 目标

应用界面上能看到当前版本号和构建时的 git commit 短 hash，例如：

```
版本   0.2.0
提交   a1b2c3d
```

有未提交改动时显示 `a1b2c3d-dirty`；取不到 VCS 信息时显示 `unknown`。
方便用户反馈问题时直接说出自己跑的是哪一份代码。

## 数据从哪来

### 版本号

统一用 `mygo.App.Version()`。它由 `mygo build` 根据 `mygo.json` 的
`version` 注入（`-X github.com/egoist/mygo.packageVersion=...`），也是
`mygo.Updater` 判断“有没有新版本”时用的值。

现在 `internal/about/about.go` 里还有一个写死的 `Version = "0.1"`，
已经和 `mygo.json` 的 `0.1.0` 不一致。应删掉这个常量，改为运行时取值。

### commit hash

Go 1.18 起，`go build` 在 git 仓库里构建时会自动把 VCS 信息嵌进二进制：

- `vcs.revision`：完整 commit hash
- `vcs.time`：commit 时间
- `vcs.modified`：工作区是否有未提交改动

`mygo build` 没有传 `-buildvcs=false`（只传了 `-trimpath`，不影响 VCS
信息），所以用 `debug.ReadBuildInfo()` 就能读到，不需要改构建参数，也不需要
额外的 `-ldflags -X`。

如果从没有 `.git` 的源码压缩包构建，或显式关闭了 VCS，取不到时回退为
`unknown`。

## 实现

### `internal/about`

不要把 `mygo` 引入 `internal/about`：`internal/gb` 和
`internal/download` 都依赖 `about`，让它们间接链接 GUI 没有必要。
由 `main` 把版本写进来，`commit` 则直接从构建信息读：

```go
package about

import (
    "runtime/debug"
    "strings"
)

// Version is the app's version, which main sets from mygo.App.Version().
// "dev" is what tests and builds without one show.
var Version = "dev"

// UserAgent identifies the app to the servers it reads from.
func UserAgent() string {
    return "MyLock/" + Version + " (+https://github.com/BabyLy233/mylock)"
}

// Commit is the short git hash the binary was built from: 7 characters,
// with "-dirty" when the working tree had changes, or "unknown" when the
// build carries no VCS information.
func Commit() string {
    info, ok := debug.ReadBuildInfo()
    if !ok {
        return "unknown"
    }
    return shortCommit(info.Settings)
}

func shortCommit(settings []debug.BuildSetting) string {
    var rev string
    dirty := false
    for _, s := range settings {
        switch s.Key {
        case "vcs.revision":
            rev = s.Value
        case "vcs.modified":
            dirty = s.Value == "true"
        }
    }
    if rev == "" {
        return "unknown"
    }
    if len(rev) > 7 {
        rev = rev[:7]
    }
    if dirty {
        rev += "-dirty"
    }
    return rev
}
```

改动点：

- 原来的 `const Version` 改成变量；`main()` 一开始执行
  `about.Version = mygo.App.Version()`，空值时保留 `"dev"`。
- `UserAgent` 从常量改成函数，`internal/gb`、`internal/download`、
  `internal/app/images.go` 里的引用同步加括号。
- 测试里没有 `main()`，`Version` 保持 `"dev"`，不影响现有测试。

### 设置页

在 `settingsPage` 底部加一节“关于”：

```go
func (a *app) aboutSection(c *ui.Context) {
    ui.Column(c).Gap(8).Children(func() {
        ui.Text(c, "关于").Bold()
        field(c, "版本", about.Version)
        field(c, "提交", about.Commit())
    })
}
```

`field` 已经存在，值是可选中的，用户可以直接复制 commit hash。
顺序放在“图片缓存”之后。

如果需要，也可以顺便显示 `vcs.time`（构建所用的 commit 时间），但当前需求
只要版本号和短 hash。

### 可选：关于菜单 / 窗口标题

- macOS 的默认 About 菜单只显示 bundle 版本，不含 commit。可以在应用菜单里
  加一项“关于 MyLock”，弹窗显示 `版本 + 提交`，或直接跳转设置页。
- 不建议把 commit 放进窗口标题：窗口标题已经用于页面标题，而且 Linux /
  Windows 的标题栏空间有限。

## 注意

- **短 hash 长度**：7 位和 `git log --oneline` 一致，足够日常使用。如果仓库
  以后变大到 7 位出现歧义，可以改成 10 位。
- **dirty 标记**：本地开发时常见，CI 构建应为干净的。如果 CI 里出现
  `-dirty`，说明构建过程改动了工作区（例如 CI 注入版本号后没有提交），
  需要检查发布脚本；这正是这个标记的价值。
- **CI checkout**：`actions/checkout` 默认浅克隆也可以，Go 只需要 `HEAD`
  和 `git status`，不需要完整历史。
- **不要在 `internal/about` 里 import `mygo`**：会扩大依赖面，尤其是让
  `internal/gb`、`internal/download` 的测试也链接 GUI 相关代码。版本由
  `main` 注入即可。
- **单一来源**：显示、User-Agent、更新检查都使用 `about.Version`
  （即 `mygo.App.Version()`），避免再次出现 `0.1` 与 `0.1.0` 并存。

## 改动清单

- `internal/about/about.go`：`Version` 改为变量，新增 `Commit()` 和
  `shortCommit()`，`UserAgent` 改为函数。
- `internal/app/app.go`：启动时设置 `about.Version = mygo.App.Version()`；
  `settingsPage` 增加 `aboutSection`。
- `internal/gb/gb.go`、`internal/download/download.go`、`internal/app/images.go`：
  `about.UserAgent` → `about.UserAgent()`。
- `internal/about/about_test.go`（新建）：测试 `shortCommit` 的完整 hash、
  短 hash、dirty、空值、畸形值。
